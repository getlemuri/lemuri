# Features in detail

- **Host tree**: nested folders, drag and drop, live reachability (a TCP probe of the SSH port every 5 minutes, every minute or never: *Settings → Servers*).
- **Import from `~/.ssh/config`**: the hosts of your SSH configuration (with `Include`, wildcards and `Host *` defaults, read like `ssh` does), each with a check box; hosts already in the list and git services start unchecked; `ProxyJump` is kept.
- **Jump hosts (ProxyJump)**: reach a server through one or more bastions, like `ssh -J`: each hop is another host of the list (with its own key or saved password) or `user@host:port`. No local port is opened, every server's host key is checked, and terminals, files and metrics all go through the same chain.
- **Real SSH terminals**: xterm.js inside the app, one tab per session across all hosts, one click on a host brings back its shell. A tab can be split side by side or one above the other (right-click on the terminal); each part is a new SSH session, on the same host or on another one. In a split tab the sync button above the console sends what you type (and paste) to every part at once, like tmux `synchronize-panes`; while it is on, every part has an amber edge.
- **Uploads over SFTP**: drag files or folders from your computer onto a terminal, or right-click it → *Upload files to the current folder*: they go into the folder the shell is in, with progress and cancel in the status bar.
- **Interactive terminal**: after `ls`, double-click a folder to `cd` into it and list it, or a text file to open it in `nano` (binary files and files over 1 MB are not opened); double-click the empty space at the prompt for `ls`. Lemuri types the command for you, visibly. You can turn it off in *Settings → Servers*.
- **Vault**: host passwords are encrypted on disk with AES-GCM, under a key derived from your master password with Argon2id (64 MiB, 3 passes); the file's parameters are authenticated too, and older vaults move to it on the first unlock. Details in [crypto.md](crypto.md). The master password can be changed in *Settings → Vault*. Key passphrases are never saved.
- **Backup and move to another PC**: *Settings → Backup → Export everything* writes one file with hosts, folders, the whole vault (passwords, your Team key, contacts) and the files of `~/.ssh` you tick: private keys (those used by your hosts are ticked already, each with its `.pub`), `known_hosts` and `config`. It is encrypted like the vault (Argon2id, AES-GCM) with a passphrase chosen for that file. *Import* adds it to what is there (without the contacts of the file: a contact is added after comparing its fingerprint) or replaces everything. A backup may carry only private keys, their `.pub`, `known_hosts` and `config`, and is refused if it holds anything else (such as `authorized_keys`); in `~/.ssh` nothing is overwritten (a different file already there stays, the imported one is saved beside it as `.imported`), `known_hosts` only gets the host keys it lacks (never `@cert-authority` or `@revoked` lines, and the import shows which servers), and `config` is not ticked for you and says if it runs commands (`ProxyCommand`, `LocalCommand`, `Match exec`).
- **Host keys checked** against `~/.ssh/known_hosts`; a new host must be confirmed by hand, and a changed key is refused like `ssh` does (fix it with `ssh-keygen -R`).
- **Saved passwords go only to password prompts**: a one-time code, token, PIN or password-change prompt is always answered by you, never with the saved password, and the background metrics connection doesn't answer it at all.
- **Live metrics**: CPU, RAM, disks and uptime read over SSH (`/proc`, `df`).
- **Team sharing**: send a host, with its password, to a contact. It is sealed for them and signed by you (X25519 + AES-GCM), and travels directly over the local network or as a block of text you send by email or chat; no server in between. Contacts are added by linking PCs on the network with a 6-digit code, or from the key line they send you, after comparing its fingerprint. See [sharing.md](sharing.md).
- **Ghost mode**: with a session open, the ghost button turns the window into a borderless, black, see-through panel on the desktop, like a conky widget: session tabs at the top, host tree on the left, the terminal in the middle, all still working. Press and hold anywhere, then drag, to move it. Four buttons stick it to the left, top, bottom or right side of the screen (press the lit one again to let it float), and F11 hides and shows it; to use F11 from any application, bind a system shortcut to `./mvnw -q javafx:run -Djavafx.args=--toggle`, run from the project folder (the copy already open does the work; Maven takes a few seconds to start). The tray icon brings back the normal window (*Exit ghost mode*, *Show Lemuri* or a click on the icon); without a tray icon the mode is not offered.
- **Tray icon**: closing the window keeps Lemuri running, with its sessions, in the system tray; quit from the tray menu.
- **Activity bar, host tree and status bar** layout, light and dark themes.
- **English and Italian**: the interface follows the system language, or the one chosen in *Settings → Appearance → Language*.
