# What runs on your servers and on the network

Lemuri only does what you see, plus one background reading over SSH, on a quiet connection that never asks for anything (keys from ssh-agent or `~/.ssh`, passwords only from the unlocked vault):

- **Metrics**: `nproc`, `/proc/stat`, `/proc/meminfo`, `/proc/uptime`, `df`. Read-only.

After a failed sign-in it waits a minute before trying again on its own, so that it does not trip fail2ban.

In the terminal, interactive mode types commands into the shell, where you see them as if you had typed them. A double-click on a folder listed by an `ls` (also an earlier one, if it ran at the same prompt: same user, host and folder) types `cd` and `ls`; on a text file, `nano`; on the empty space at the prompt, `ls`. Before typing, Lemuri asks the shell for its folder with a `printf "$PWD"` whose output is not shown, and looks at the name over SFTP on the same connection (on the disk, for a local shell): binary files and files over 1 MB are not opened, and a note near the mouse says why. Uploads into the terminal's folder ask for the folder the same way. You can turn all of this off in *Settings → Servers*: then uploads go to the home folder. Lemuri types into the terminal only when the cursor sits on what looks like an empty shell prompt (`user@host:dir$`, `[user@host dir]#`, `user@host dir %`). This keeps it out of `mysql>`, REPLs, sudo password prompts, running commands and lines you have started typing, but it is a best-effort check on the text on screen: a program that prints a line looking exactly like a prompt can fool it. These commands start with a space, so they stay out of the history if `HISTCONTROL` includes `ignorespace` (the default on Ubuntu).

## Network behaviour

- **SSH** to your hosts (through their jump hosts, if they have any: the connection to the next server is a `direct-tcpip` channel of the jump session, as with `ssh -J`, so the jump host must allow TCP forwarding), and a TCP connection to each host's SSH port every 5 minutes to show whether it is reachable (every minute or never, in *Settings → Servers*; with never, only when you press Refresh) (no login; for a host behind a jump host, the first hop's port): it exchanges the SSH version line and closes. sshd logs one line for each of these connections (about 290 a day per host every 5 minutes, 1,440 every minute, such as `Connection closed by … [preauth]`). The version exchange avoids the messages that fail2ban's sshd filter counts as attempts in its `ddos` and `aggressive` modes (connections closed before it); this has not been tested against every fail2ban version, so check it on a test server if you use those modes.
- **Local network sharing** (off by default; turn it on in *Team*): when on, Lemuri announces itself every 5 s with a UDP broadcast on port 47820, on private networks only, with your `user@hostname` and public key (never your email), and listens on TCP port 47821. It accepts connections only from private addresses (10/8, 172.16/12, 192.168/16, link-local, fc00::/7, 100.64/10), with limits on connections, unknown PCs and link requests. Hosts are accepted only from your contacts, and you still accept each one. Turn it on only on networks you trust: on public Wi-Fi others can see that you run Lemuri.
